Q5: Which of gprof and gcov is faster and why?
A5: gprof, as stated above, is faster than gcov, as gprof is a statistical profiler- periodically samples program counter during execution, where gcov doesn't sample, it instruments every single branch/line of code 
Sampling has much lower overhead than instrumentation, hence gprof being faster

Q15: For the "number-one" function for -O3 (the one with the greatest percentage execution time), how does its percentage execution time compare with the percentage execution time for the same function in the -g version? How is this possible? What transformation did the compiler do and to which functions?
A15: The top fucntion in terms of runtime for -O3 is now processRotateCCWReference, compared to processRotateCWReference for the -g optimization.
In the -g version, calls to processRotateCWReference are done within processRotateCCWReference, which adds overhead.
In the -O3 version, the compiler inlined the CW function directly into the CCW function which eliminates calling overhead, and the profiler no longer sees separate functions. 
Merging the callee into the caller makes the caller's function appear longer because it now contains all of the computations being done.
